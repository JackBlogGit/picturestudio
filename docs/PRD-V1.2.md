19. **加密空间定稿并落地（D26）** —— 第 18 章最后的开放大问号「真加密 or 档位更严的隐藏文件夹」选定**客户端信封加密**：口令在浏览器里经 PBKDF2-SHA256（210,000 轮）派生 AES-256-GCM 密钥，**文件名与字节都在本地加密后才出网**，服务端只存密文 + 盐 + 校验子；因此**忘记口令 = 内容永久不可恢复**（无托管、无重置，唯一出路是销毁本空间），**没有「解锁」接口**，密钥只活在组件内存里；**超管对他人空间止于「条数 + 容量 + 删除」**，`nameCipher` 与密文字节一律不下发（`private` 档的一条特例，3.1 / D1 / D19 需并列阅读）。改口令走 `POST /vault/rekey` **一次带走整空间重封密文**、参数最后才换，避免永久不可解的中间态；条目**就地销毁、不进垃圾箱**；加密**不是 5.2 黑名单的后门**。**新增 5.7 与 10.7**，改动落在 2 / 8.4 / 8.5 / 11 / 15 / 18 / 19 章。**已在 `client/` 落地**（`utils/crypto.ts` + `api/vault.ts` + `api/mock/vault.ts` + `views/VaultView.vue` + 路由 `/drive/encrypted`，宫格那一格不再弹「尚未实现」），**只在 mock 下自测过**（headless Edge 逐身份 45 项断言全绿，脚本 `output/verify-vault.mjs`）；server 侧 `VaultModule` 与两张新表属 **M4 网盘**范围，尚未实现。

## 1. 项目定位

面向 Cos 摄影工作室 / 社团摄影团队的专属 Web 平台，整合两条业务线：

1. **漫展标签化返图交付** — 现场传图 → 打标签 → 筛选 → 按 coser 单人精准交付。
2. **多级权限文件共享网盘** — 后期工作文件沉淀、团队共享、外聘人员临时协作。

三种身份共用一套资源权限模型：四级正式成员、临时账号、游客。

核心能力清单：四级精细化成员权限、自定义临时账号/限时链接、无登录游客只读模式、多标签返图系统、树形目录网盘、操作日志审计、资源权限管控与安全防护。

## 3. 全局规则与通用定义

### 3.1 资源可见范围

相册、图片、文件夹、文件四类资源共用同一套枚举，**严格度递增**：

`public（公开）` < `member（成员可见）` < `admin（仅管理员）` < `private（私有）`

> 注：V1.0 表述为「权限优先级 私有 > 仅管理员 > 成员可见 > 公开」易被误读为「多规则冲突时取私有」。此处明确：该顺序是**严格度序**，用于计算继承上限（见 3.2），不是冲突仲裁序。单个资源永远只有一个 `visibility` 值。

| 档位 | 可访问主体 | 原图 / 原文件下载 |
|---|---|---|
| `public` | 游客 + 临时账号 + 全部正式成员 | 游客与临时账号默认禁止；L1 禁止；L2/L3/L4 允许 |
| `member` | 仅 L1–L4 正式成员 | L1 禁止；L2/L3/L4 允许 |
| `admin` | 仅 L3、L4 | L1 无预览权；L3/L4 允许下载 |
| `private` | **仅资源归属人本人 + L4 超管** | 归属人与 L4 允许 |

### 3.2 继承上限规则（新增，D3）

资源的有效可见范围 = `max(自身 visibility, 父容器 visibility)`（按 3.1 严格度序取更严的一档）。

- 图片必须满足 `rank(image.visibility) >= rank(album.visibility)`
- 文件夹与文件必须满足 `rank(自身) >= rank(祖先链上任一节点)`
- **写入时校验**：子资源试图设得比父容器更宽松 → 返回 `409`，提示「需先放宽上级 {相册|文件夹} 的权限」
- **父容器放宽时**：不自动传染子资源。管理员把相册 `member → public`，若相册内存在 `member` 图片，系统弹窗要求二选一：①「同步放宽全部子资源到 public」②「仅放宽相册本身，内部图片保持 member」（此时游客只见相册壳，不见图）
- 私有资源不参与任何列表聚合，仅在归属人自己的「个人中心」和 L4 的全站视图里出现

### 3.3 三类身份

| 身份 | 来源 | 会话载体 | 后台可见性 |
|---|---|---|---|
| 四级正式成员 | 后台手动创建（无注册入口） | JWT，含 `uid` + `level` | 是 |
| 临时账号 | 仅 L3/L4 创建 | JWT（含 `temp_id`）或凭 `access_token` 直连 | 是，独立列表 |
| 游客 | 匿名访问 | 无 | 否 |

三类身份权限完全隔离，不存在继承或叠加。一个会话只能是其中一种。

## 4. 漫展标签返图系统（核心业务）

### 4.1 标签体系

五大类型，图片与标签多对多，支持双人 cos / 多角色同框：

| 类型 | 语义 | 示例 | 谁可增删改 |
|---|---|---|---|
| `event` | 漫展 | `2026-09 本地次元漫展` | L2+ 输入即建（自动去重） |
| `coser` | Coser 昵称，**核心交付标签** | `柚子` | L2+ 输入即建 |
| `role` | 作品-角色 | `原神-雷电将军` | L2+ 输入即建 |
| `photographer` | 拍摄者 | `阿哲` | L2+ 输入即建 |
| `status` | 内部状态：待修 / 已修 / 废弃 | `待修` | **仅 L3/L4 可增删标签本身**；成员可给自有图片打已有状态 |

规则：
- 输入框自动补全，命中 `tag_name` 与 `alias`，杜绝重复标签（DB 层 `UNIQUE(tag_type, tag_name)` 兜底）
- 同一图片在同一 `tag_type` 下允许多个标签（多角色场景）
- **`status` 标签对外一律不下发**：游客接口、分享链接接口、临时账号接口返回的 tags 数组均需过滤 `tag_type='status'`
- 标签合并：`tags.merged_into` 指向目标标签，历史关联由任务迁移后停用原标签，不物理删（保留频次统计）

### 4.2 相册管理

一个相册对应一场漫展。字段：名称、漫展名称、漫展日期、地点、简介、封面图、可见范围、状态、创建人。

- 状态三值：`1 正常` / `2 归档`（前台不展示，成员可查）/ `3 锁定`（禁止上传、编辑、改标签，仅可浏览与下载）
- 创建相册即绑定 `visibility`，成员默认只能建 `member` 或 `private`
- 封面替换从相册内已有图片选取；删除封面图时应用层清空 `cover_img_id`（该列刻意无外键，避免与 `images.album_id` 循环引用）
- 删除相册为**物理删除并级联删除全部图片**，不可恢复 → 前端二次确认（要求输入相册名），后端写 `logs`
- 权限：`private` 相册对 L3 完全不可见（D1）

### 4.3 图片上传

- 批量拖拽上传，移动端适配（漫展现场手机直传）
- 走分片上传通道（见 5.3），小图（< 5MB）单请求直传
- 原图与预览图**分目录独立存储**，二者访问路径均不可直接静态访问
- 自动生成三种产物：原图（无损保留）、预览图（长边 2048px）、缩略图（宽 400px）
- **自动读取 EXIF `DateTimeOriginal`** 写入 `images.shot_time`；无 EXIF（截图 / 后期图）则留空，由上传者在详情页补填
- RAW 格式（`.cr2/.nef/.arw/.raw`）允许上传存档，但后端无法生成预览 → 缩略图用嵌入 JPEG 预览回退，失败则占位图
- 水印：按站点配置决定是否给**预览图与缩略图**叠加（D7），原图永不修改；`watermarked` 标记记录该图生成时是否带水印
- MD5 查重：同归属人已存在相同 MD5 → 返回 `409`「该图片你已上传过」，附已存图片链接，前端允许「仍要上传」（放行后写新记录，文件复用同一路径）
- 上传完成后进入「待打标」态，支持批量绑定标签 + 单张微调

### 4.4 返图筛选与交付

**多维组合筛选**（相册详情页顶部）：漫展、coser、角色、摄影师、图片状态，条件之间为 AND，同类型多值为 OR。筛选走 `image_tag_map` 的 `idx_tag` 反查 + `GROUP BY image_id HAVING COUNT(DISTINCT tag_id)=N`。

**Coser 专属返图分享链接**（核心交付功能）：

配置项 — 有效期、访问密码（可选）、是否允许原图下载、命中方式（动态 / 快照）。

- `snapshot=0`（默认，动态）：访客每次访问时按 `album_id + coser_tag_id` 实时命中，新上传并打上该 coser 标签的图片会自动出现，无需重发链接
- `snapshot=1`（快照）：生成时把当前筛选结果固化进 `share_link_images`，用于筛选条件含角色/摄影师等复合条件的场景（`filter_json` 保存原始条件供追溯）
- **权限绕过范围（D2）**：链接有效期内，访客可见 = 该相册内命中筛选条件的图片预览，**忽略这些图片自身的 `visibility`**，但：
  - 相册 `visibility` 为 `admin` 或 `private` 时**禁止生成链接**（`403`，提示先改为 public/member）
  - 访客只能命中集合内的图片，不可枚举、不可进入相册详情页、不可看到相册内其他任何图片
  - 命中集合外的图片 ID 被请求时返回 `404`（不是 403，避免暴露 ID 存在性）
  - 不下发 `status` 标签，不下发上传者账号信息，不下发其他 coser 名字
- `allow_download=1` 时访客可下载该集合内的**无水印原图**；`=0` 时仅提供预览图 + 带水印
- 密码保护：`password` 存 bcrypt，验证通过后签发 2 小时有效的链接子会话（Cookie，`HttpOnly` + `SameSite=Lax`），绑定 `share_token`
- 过期或被 `revoked` 后永久失效；链接访问计入 `visit_count` 与 `logs`
- L1 与临时账号不可生成链接

### 4.5 批量操作

批量加/移除标签、批量改状态、批量改可见范围、批量重新生成水印、批量打包 ZIP。

- 打包 ZIP：L2/L3/L4 可用；**L1 与游客禁用**；临时账号需 `allow_download=1`
- 单次批量上限 500 张，ZIP 为流式生成（不落临时盘），超时 10 分钟
- 批量改可见范围时必须逐条跑 3.2 继承校验，不合规项列清单返回，不静默跳过
- 批量删除：仅 L2（自有）/ L3 / L4；L1 禁用

### 4.6 标签后台管理（L3/L4）

标签库全量列表、重命名、合并重复标签、删除无效标签、按 `use_count` 排序统计与清理冗余。`status` 类型标签为内置，仅允许改文案不允许删。

## 5. 文件共享网盘模块

### 5.1 定位

独立于返图相册的第二存储域，存后期源文件、预设、合同、素材、样片等。树形多级目录，每个文件夹独立配权。

### 5.2 文件类型

白名单由 `site_settings.upload.file_extensions` 配置，默认允许：图片、PDF、Word/Excel/PPT、PSD、AI、ZIP/7Z/RAR、MP4/MOV、预设文件。

**扩展名白名单 + 二进制头校验双重把关**：用 `file-type` 读 magic bytes，实际类型不在白名单一律拒收；黑名单（`.exe/.bat/.sh/.msi/.dll/.apk/.jar/.js/.vbs/.ps1/.scr`）无条件拒绝，即使命中图片白名单也拒。`mime_type` 落库存**校验后的真实类型**，不信任客户端上报的 Content-Type。

### 5.3 核心功能

- **树形目录**：`folders.path` 物化路径（`/1/5/12/`）+ `depth`，最大 8 层，取子树走 `path LIKE '/1/5/%'` 命中 `idx_path`，避免递归查询。同级重名由 `UNIQUE(parent_id, name)` 约束（注意 MySQL 允许 `parent_id` 为 NULL 时重复，**顶级目录重名需在应用层额外校验**）
- **文件夹移动**：需重算整棵子树的 `path` 与 `depth`（单事务内批量 UPDATE），并禁止移动到自身子孙下（防环，校验 `target.path` 不以 `moving.path` 开头）
- **断点续传**：客户端分片（默认 5MB）→ `upload_sessions` 记录已收分片下标 → 刷新/断网后凭 `upload_id` 拉取缺失分片续传 → 全片齐后服务端顺序合并、算 MD5 与 `md5_client` 比对 → 建 `files` 记录。会话 24 小时过期，未合并碎片由定时任务清理
- **上传目的地（原型图 1）**：网盘页「上传」标签页（D18）顶部的「上传目的地」输入框是**目标文件夹选择器**，取值为 `folders` 树中当前身份可写的节点（无权分支不出现在候选里，`＋` 就地新建子目录）；未选目的地时默认落到 `/`（顶级），临时账号则只能落到白名单命中的文件夹。目的地在**整批任务级别**生效，批次内每个文件各自的相对路径在其下展开
- **待传清单（原型图 1「上传文件」长框）**：目的地下方那条长框 = 当前批次的**待传文件清单 + 拖放区**（判读待复核，见 8.5 ⑤）。本地选择或拖入文件/文件夹后在此逐行列出：文件名、大小、相对路径（整批上传时）、单文件进度、失败原因与跳过项；行末可逐个移除，顶部可清空整批。「本地上传文件」「本地上传文件夹」两枚按钮只是**选择器入口**，不直接开传，确认目的地后才提交整批
- **文件夹整体上传（D12）**：`webkitdirectory` 读取 `File.webkitRelativePath`，先在目标目录下按相对路径**幂等建出同名目录树**（`ensurePath`：逐级查同名子目录，缺则建，命中即复用），再逐文件走断点续传。约束：单次 ≤ 2000 个文件、相对深度 ≤ 10 层（超出 5.3 树深上限的整批拒绝）、总大小受配额约束、同名文件不覆盖而追加 `(1)`、`(2)`；`.svg` 与 5.2 黑名单扩展名在批次内**静默跳过**并在结果里列明原因；任一文件建目录失败即整批回滚已建目录，不留半成品
- **上传 / 下载任务面板（D13）**：`/drive` 的**一级标签**「文件 | 下载中 | 已完成 | 上传」与「上传」标签内的**二级标签**「上传 | 上传中 | 已完成」（层级划分见 D18）是**同一套前端任务队列的两个视图**，状态存 Pinia store，刷新即丢、不跨设备恢复；后端不提供「我的下载历史」接口。仅 ZIP 打包是服务端任务，走 BullMQ 并写 `logs`，面板用轮询 `GET /drive/files/batch-zip/:taskId` 拿进度
- **在线预览**：图片直出、PDF 用浏览器原生渲染、MP4 走 HTTP `Range` 分片响应（支持拖动进度条）。PSD/AI 仅给缩略图，不承诺完整渲染
- **元数据**：文件名、大小、真实 MIME、MD5、上传人、上传时间
- **下载**：单文件直下、多文件流式 ZIP、分享链接生成（可设有效期 + 密码 + 允许下载次数）
- **空间配额**：见 5.6

### 5.4 权限控制

完全复用全局权限模型与 3.2 继承上限规则。游客禁止访问一切网盘资源（分享链接通道除外）。L1 可预览 `public`/`member` 文件，但禁止下载与打包。

- **超管个人授权**：`drive.perm*` 四档门槛是全站统一的等级闸门，改一处影响所有人。超级管理员可以在成员管理页单独给某一位成员「开启」其中一档文件权限（个人授权），让该成员绕过那一档的门槛，而门槛值本身不变、其他人不受影响。个人授权落库在 `users` 表的四个开关列上，判定与等级门槛取并集（任一满足即放行）。垃圾箱（规则 12）与爬虫（规则 11）不参与个人授权，仍只有超管能进。

### 5.5 临时账号的网盘授权（新增）

`temp_account_folders` 白名单授权**级联包含该文件夹的全部子孙**（因为子资源可见性受祖先约束，授权父目录即授权其内容）。有效权限 = 白名单命中 ∧ `allow_preview` / `allow_download` / `allow_upload_file` 各开关。

### 5.6 存储空间配额（新增，明确语义）

- `space_quota`：`0` = 不限；正数为字节上限
- `used_space`：实时累计，计入该用户名下**全部** images.file_size 与 files.file_size（含 `private`）
- 更新时机：上传成功建记录时 `+file_size`，删除资源时 `-file_size`，必须在同一事务内，否则配额失真
- 校验：上传前比较 `used + 待传大小 <= quota`，超限返回 `413`，前端提示「空间不足，已用 X/Y」
- **预览图与缩略图的体积不计入配额**（配额按原图/原文件计），但后台仪表盘单独统计衍生副本占用，供容量告警
- L4 在用户管理页可改配额；临时账号有独立 `space_quota`，不占用 owner 的配额

### 5.7 加密空间（新增，D26 客户端信封加密）

每人一个只属于自己的私密盘子，放摊位合同、分成比例、约稿收据这类「不该进档位体系」的文件。入口是首页宫格「加密文件」→ `/drive/encrypted`（网盘下的独立页，与 `/drive` 同一道闸门 `meta.auth + meta.member`）；**可见性与准入按 D19**：L1–L4 四级各有自己的空间，临时账号与游客 ❌（手敲 URL 时游客 401、临时账号 403）。档位语义仍归 `private`（3.1），但**超管在这一档的权利被客户端加密压到「容量 + 删除」为止**，见下面「超管边界」。

**加密发生在浏览器里，服务端只存密文**——这是 D26 与「服务端 AES-GCM 信封」两条路里选定的一条，代价与收益都写在下面。

- **口令 → 密钥**：PBKDF2-SHA256，默认 `210_000` 轮 + 16 字节随机盐（初始化时由前端生成并随参数上传），派生出 **AES-256-GCM** 密钥。**文件名与文件字节都在本地加密完成后才出网**，服务端与网络中间人见到的只有密文容器
- **密文容器格式**：`[版本 1 字节][IV 12 字节][密文 + GCM 认证标签 16 字节]`。因此 **密文体积 = 明文体积 + 29 字节**，每条上传都会比原文件大一点，这不是 bug 而是格式开销；配额按**密文体积**计（5.6 的「计入 `private`」在这里同样适用），页面同时登记明文体积，只用于容量视图对照
- **域分离**：三类用途各自的 `additionalData` 常量——文件名 `pikevault.name`、文件字节 `pikevault.blob`、口令校验子 `pikevault.check`。少这一层，一条容器就能被挪作他用（把文件密文冒充校验子、把甲的文件名塞到乙的条目上），GCM 不会报错，语义却全错
- **口令校验子 = 没有「解锁接口」**：初始化时前端用同一把密钥加密一段本地已知串，作为 `verifier` 随参数上传；解锁时把输入口令派生成密钥、**在本地尝试解开校验子**，解得开就算口令对。于是登录态里没有任何「解锁」请求，**口令从不出页**，也不出现在任何请求体、URL、日志里
- **密钥只在组件内存里**：不落 `localStorage` / `sessionStorage` / IndexedDB，点「锁定」、切页、刷新都要重新输口令。这不是多余的谨慎，而是「忘记口令不可恢复」的另一半——只要密钥有地方能被浏览器自动取回，口令就形同明文存在
- **忘记口令 = 内容永久不可恢复**：服务端只有盐、轮数、校验子与密文，**没有托管密钥、没有重置途径、没有任何人能替你解开盘子**。唯一出路是「**销毁本空间**」（`POST /vault/destroy`）：清空全部密文与派生参数、回到未初始化状态、配额归还。该动作要求**打字确认**（输入「销毁」二字），文案必须写明不可恢复
- **改口令是一次原子的整空间重封**：`POST /vault/rekey` 同时带走「新派生参数」与「**每一条**重封好的密文」（旧密钥本地解 → 新密钥本地重封）。服务端**两趟处理**——先整份校验（条目集合是否与空间实际条数一一对应、每条容器长度是否与登记的 `cipherSize` 相符），全部通过后才提交并**最后一步才换参数**；中途任何失败都保持旧口令继续可用。条目数不符 → 409 `REKEY_SET_MISMATCH`，重封后超配额 → 413 `QUOTA_EXCEEDED`。**不做「先换参数、再逐条重传」**，那种写法一旦中途断掉就会留下「空间已是新密钥、某条密文还是旧密钥」的条目，那条永久解不出来
- **超管边界（`private` 档的特例，与 3.1 / D1 / D19 并列阅读）**：L4 进得了任何人的空间、看得到**条数与体积**、**能删**，但**拿不到文件名密文与密文字节**——`GET /vault/files?owner=` 里非本人的行 `nameCipher` 与 `links.cipher` 一律 `null`，`GET /vault/files/:id/cipher` 对非归属人一律 404。两条理由：① 客户端加密下他本来就解不开，把密文连同盐与轮数一起下发只是给他**离线爆破的素材**（容器 + KDF 参数可以慢慢试口令）；② **删除权不该顺带变成读取素材**。因此 3.1 的「`private` = 归属人本人 + L4」在这一档下要读作「**L4 可管理与可销毁，不可解密**」
- **低权限探他人空间**：L1–L3 带 `?owner=` 查别人 → **404 而非 403**（D1 的口径：不向低权限身份泄露该空间是否存在）；`GET /vault/spaces`（成员空间总览）仅 L4，L1–L3 → 403，表里只有容量与条数两列可看
- **加密不是 5.2 黑名单的后门**：上传时前端随元数据带小写扩展名，命中黑名单一律 415 `EXTENSION_BLOCKED`。理由不是「服务端能看出内容」，而是**不让私密空间变成投放可执行文件的仓库**——把 `.exe` 加密塞进某人空间，再诱使他自己解密下载运行，等于绕过了整条 5.2 防线
- **单文件上限更紧**：站点配置新增 `vault.max_file_size`（默认 50MB），比 `upload.max_file_size` 小，因为密文**整块提交、不参与 5.3 的分片断点续传**（分片会话要把明文切块，与「明文不出页」直接冲突）；超限 413 `FILE_TOO_LARGE`
- **不进垃圾箱**：条目删除即**就地物理销毁**（`DELETE /vault/files/:id` → `{ purged: true }`）。规则 12 的垃圾箱是超管能逐条看见并还原的**明文清单**，往里塞一条谁也解不开的密文只会让人误以为存在还原途径；还原无从谈起，所以二次确认必须写明「不可恢复」，审计 `detail` 只记密文体积
- **审计**：`logs` 新增动作 `vault_setup` / `vault_rekey` / `vault_upload` / `vault_delete` / `vault_destroy` / `vault_admin_view`（超管查他人空间汇总时留痕）。所有 `detail` **只允许出现体积、条数、扩展名、目标 uid**，绝不含口令、盐、校验子、密文片段（12.11 的同一条要求）
- **落地现状**：`client/` 已完成并在 mock 下端到端自测通过（内核 `utils/crypto.ts`、接口层 `api/vault.ts`、mock `api/mock/vault.ts`、页面 `views/VaultView.vue`，路由 `/drive/encrypted`）。**server 侧 `VaultModule` 尚未实现**，表与列见第 19 章，接口清单见 10.7。关掉 mock 接真后端时页面代码不变——传输差异（mock 把密文 base64 混在 JSON 里，真接口改 `PUT application/octet-stream`）收在 `api/vault.ts` 一层，与 `upload.ts` 的 `putChunk` 同一套写法

## 6. 用户权限体系

### 6.1 四级正式成员

**L4 超级管理员**
- 全站配置：站点参数、水印配置、上传限制、文件白名单、存储配置
- 用户管理：增删改、禁用、重置密码、调整等级、配置空间配额（对 L1–L3 全部可操作）；**逐项管控任何一个人的功能权限**（11 个能力位按人设「跟随等级 / 强制开 / 强制关」，见 6.4，D21）
- 资源管理：所有相册、图片、文件夹、文件，可删除任意资源
- 临时账号：创建、销毁、管理全部
- 日志审计：全站所有操作记录
- 访问 `private` 资源（唯一可查看他人私有内容的角色）
- 无任何访问 / 上传 / 下载 / 操作限制
- **不可被删除、不可被降级、不可被禁用**；不可被其他 L4 操作（系统仅允许存在一个 L4，见 12.4）

**L3 普通管理员**
- 成员管理：L1、L2 的新增、禁用、重置密码、调整等级、**配额设置**；无法操作 L4
- 临时账号：创建、销毁、配置各项权限
- 资源管理：审核与管理全站 public/member/admin 三档资源，批量修改其权限；**不可访问他人 private 资源（D1）**
- 上传、下载、编辑 public/member/admin 资源；可编辑他人资源的标签
- 可生成任意 coser 返图分享链接
- 标签库管理、留言审核、日志查看（本人与他人）
- 无权限：修改站点核心配置、删除超管、清空全站数据

**L2 普通成员（摄影师 / 后期正式成员）**
- 自主上传返图与工作文件
- 管理个人上传的全部资源（编辑标签、重命名、移动、删除）
- 预览、下载 public 与 member 的相册及文件；管理自有 private 资源
- 为自有图片添加五类标签（`status` 仅可选已有值）
- 多维筛选返图、生成自有图片的 coser 专属分享链接
- 建相册、归档/锁定自有相册
- 无权限：管理他人账号、修改他人资源、任何后台管理入口

**L1 见习成员（新人 / 实习）**
- 上传个人返图与工作文件，自主编辑个人资源标签
- 预览所有 public 与 member 资源
- **禁止**：一切原图 / 原文件下载、ZIP 打包下载
- **禁止**：删除任何图片与文件（**含个人上传**）、删除相册与文件夹
- **禁止**：生成 coser 返图分享链接、任何批量操作
- **禁止**：创建相册？—— V1.0 未写明，V1.1 定为**可以创建相册**（否则无法上传返图），但其相册不可设为 public（对外发布需 L2+）
- 无任何用户管理、后台配置权限

### 6.2 临时账号体系

**适用**：漫展现场外聘摄影师、合作 coser、临时后勤，短期协作，免注册，到期自动失效。**同时是第 17 章返图工单的宿主**（D10：一账号 = 一工单）。

**创建主体**：L1–L4 均可创建（D9，替代 V1.1「仅 L3、L4」）。L1/L2 创建的账号由后端**强制降权**，前端传什么都不生效：

| 约束 | L1 / L2 创建时 | L3 / L4 创建时 |
|---|---|---|
| 有效时长 | ≤ 7 天，超出即截断为 7 天 | 1 小时 ~ 30 天自定义 |
| 权限开关 | 默认仅 `allow_preview` + `allow_upload_img`；`allow_download` / `allow_upload_file` / `allow_edit_tag` 恒为 0 | 五项自由组合 |
| 空间配额 | 取站点配置 `temp.default_quota`，不可自定 | 自由填写 |
| 资源白名单 | 只能选**自己上传的**相册 / 自己建的文件夹 | 全站任意 |

配置项：

| 配置 | 说明 |
|---|---|
| 帐户ID | `account_no`，**全局唯一、系统生成**，格式 `YK` + 6 位随机大写字母数字（去掉易混字符 `0O1IL`），冲突则重生成，最多 5 次后 500。登录页可用它替代 `login_name` 登录。**D23：仅 L4 可在后台编辑修改，更改后需二次确认并告知共享目录名将同步更新、旧 ID 立即失效** |
| 访问方式 | ①`login_name` 或 `account_no` + `password` 登录页登录；②`access_token` 一次性专属链接直连（可叠加 `password` 验证）。**至少配一种**，两者皆空则创建失败 |
| 密码 | bcrypt(cost 12)；创建表单需**二次确认**，两次不一致前端直接拦，不发请求。**D23：L4 可在后台编辑弹窗设新口令（留空=不改），审计日志不含明文** |
| 手机号 | `phone`，可空，11 位大陆号段正则。**PII**：仅 owner 与 L3/L4 可见完整值，其余身份与一切 API 响应、`logs.detail` 均脱敏为 `138****8000` |
| 昵称 | `display_name`，用于返图页与上传页的署名展示 |
| 拍摄内容 | `shooting_note`，选填，≤ 500 字，描述本次漫展返图/拍摄任务内容（工单标题性说明） |
| 后期前效果 | `pre_refs`：选填，0–9 张参考图，走网盘上传，落 `files` 并以 `temp_account_id` + `stage='pre'` 关联；仅用于向后期说明预期效果，**不下发给游客，不进分享链接** |
| 有效时长 | 表单按「天」下拉（1/3/7/15/30 天 + 自定义起止），后端统一折算为 `expire_time` 绝对时刻 |
| 资源白名单 | `temp_account_albums`（相册级，含其内全部图片）+ `temp_account_folders`（文件夹级，含全部子孙）。白名单为空 = 无任何资源访问权，仅可上传到指定投递目标 |
| 权限开关 | `allow_preview` / `allow_download` / `allow_upload_img` / `allow_upload_file` / `allow_edit_tag` |
| 空间配额 | `space_quota`，独立于 owner |
| 归属人 | `owner_uid` = 创建该账号的成员（L1/L2/L3/L4 皆可，D9 后不再限定管理员） |
| 修图阶段 | `pre_stage` / `post_stage` + 两个完成时间，见第 17 章。创建时恒为 `0`（未完成），不接收前端入参 |

**表单控件 ↔ 接口对照（原型图 3）**

| 原型控件 | 行为 | 接口 |
|---|---|---|
| 帐户ID 输入框（预填 `YK…`） | 打开表单即预生成一个候选 ID | `GET /api/v1/temp-accounts/next-account-no` |
| 「换一下」 | 重新生成候选 ID，不落库 | 同上 |
| 密码 + 再次确认 | 前端比对，不一致不发请求 | — |
| 「手机号」 | 选填输入 | — |
| 「复制帐号信息」 | 把 `帐户ID / 密码 / 专属链接` 三行拼成纯文本写剪贴板；**密码只在创建成功那一次随响应返回**，之后任何接口都不再返回 | `POST /temp-accounts` 的响应体 |
| 「拍摄内容」 | 多行文本 | — |
| 「账号时长 __ 天」 | 下拉，L1/L2 的选项列表由后端下发的 `max_days` 裁剪 | `GET /temp-accounts/schema` |
| 「后期前效果」+「本地上传文件」 | 先传文件拿 `file_id` 列表，再随表单提交 | `POST /drive/files` → `POST /temp-accounts` |
| 「创立」/「取消」 | 提交 / 放弃（不占用已生成的候选 ID） | `POST /temp-accounts` |

核心规则：
- 无后台管理权限、无法查看用户列表、无法修改站点配置、无法生成分享链接
- **上传资源自动归属工作室**：写入 `upload_uid = temp_accounts.owner_uid`、`upload_temp_id = temp.id`，账号到期后资源永久保留（外键 `ON DELETE SET NULL` 只清身份标记，不清资源）
- 管理员可提前手动销毁（`disabled=1`，立即失效，已签发的 JWT 靠 15 分钟短 TTL + Redis 黑名单兜底）
- **临时账号亦可自助销毁**（D15，图 9「一键销毁帐号」格）：仅销毁自己这一个账号，需二次确认，走 `POST /auth/temp-destroy`（10.1）。销毁与到期销毁走同一条落库路径（`disabled=1`），**已上传资源一律保留**、归属仍为 `owner_uid`，不可逆、无回收站、不提供找回；owner（L1–L4）在后台仍能看到该账号及其资源，状态显示为「已销毁（本人操作）」
- 失效账号无法登录、无法访问任何资源，历史访问日志保留
- 临时账号可访问范围内，`private`/`admin` 资源仍需白名单显式命中才可见（白名单即授权，可覆盖档位），但 `status` 标签一律不下发

### 6.3 游客模式

- 无需注册登录，直接访问前台
- 仅可浏览 `public` 相册的预览图（且图片自身也为 `public`）
- 禁止访问全部网盘资源、禁止查看 member/admin/private 资源
- 禁止原图下载、文件下载、任何上传操作
- 隐藏内部状态标签，仅展示漫展与角色标签
- 首页相册列表按 `visibility='public' AND status=1` 过滤
- **唯一例外**：持有有效 coser 分享链接时，按 4.4 的绕过规则访问命中集合
- **游客仅有的两个功能入口（D22）**：展示首页 `/` 的「快捷入口」区渲染**两格**——**取图** `/take`（贴 coser 分享链接或其 token，跳 `/s/:token` 走上一条例外）与**联系我们** `/contact`（公开联系方式页，内容来自 `site.contact`）。两页都**不挂登录守卫**，但也不给游客任何别的动作：不可批量存图、不可上传、网盘与后台仍不可达。除此之外游客在 `/` 上看不到任何功能格，未授权的入口**不渲染**（不是置灰），避免暴露功能存在性。
- 游客留言（可选功能，由 `guest.comment_enabled` 开关）：需 L3/L4 审核通过后才公开展示，`contact` 字段仅管理员可见

### 6.4 个人功能授权（超管逐项管控，D21 新增）

6.1 的等级描述与 7.2 的矩阵给出的是**默认能力位**，不是天花板。L4 可以在默认值之上对**单个人**逐项覆盖，覆盖只影响这一个人——站点配置不动、别人的权限不动、也不用为了「就给他一个人开一下下载」而把他调级（调级会同时改动他的一整片权限与后台可见范围，副作用远大于目的）。这是把 D20 的网盘个人授权范式推广到全部功能位。

**能力位 × 等级默认值**（`GET /auth/me` 的 `capabilities` 就是这一列算出来的，前端只认这一组字段，不再自己抄规则）：

| 能力位 | 界面文案 | 控制什么 | L1 | L2 | L3 | L4 | 超管可改 |
|---|---|---|---|---|---|---|---|
| `download` | 原图下载 | 原图 / 原文件单件下载（不含预览） | ❌ | ✅ | ✅ | ✅ | 双向 |
| `zip` | 批量打包 | 多选打包、ZIP 下载（4.5） | ❌ | ✅ | ✅ | ✅ | 双向 |
| `upload` | 上传 | 传图与传文件（写档仍受 3.2 与目标可写性约束） | ✅ | ✅ | ✅ | ✅ | 双向 |
| `editOwn` | 编辑自有 | 编辑自己上传资源的标签 / 重命名 / 元数据 | ✅ | ✅ | ✅ | ✅ | 双向 |
| `editAny` | 编辑他人 | 归属范围开关：开 = 全站，关 = 收窄到仅自有 | ❌ | ❌ | ✅ | ✅ | 双向 |
| `delete` | 删除 | 删除图片 / 文件 / 相册 / 目录 | ❌ | ✅（自有） | ✅ | ✅ | 双向 |
| `changeVisibility` | 改档位 | 修改资源可见范围 | ✅（自有） | ✅（自有） | ✅ | ✅ | 双向 |
| `canSetPublic` | 对外发布 | 把资源档位设为 `public`（6.1 L1 对外发布需 L2+） | ❌ | ✅ | ✅ | ✅ | 双向 |
| `shareLink` | 返图链接 | 生成 coser 分享链接（4.4） | ❌ | ✅（自有） | ✅ | ✅ | 双向 |
| `adminConsole` | 后台入口 | `/admin` 及其全部子页（8.2） | ❌ | ❌ | ✅ | ✅ | 双向（唯一 L4 不可关，见下） |
| `writeSiteSettings` | 站点配置写入 | `PUT /admin/settings`（10.5） | ❌ | ❌ | ❌ | ✅ | **保留位**：不可下放给 L1–L3 |

- `editAny` 收窄的是**归属范围**而不是只有标签编辑：关掉它，这个人的 编辑 / 删除 / 改档位 / 生成链接 四项一起退回「仅自有」。要表达「管理员只管自己的活」，关这一位就够，不必逐位关。
- 能力位只管**动作**，不管**可见范围**：一个人能看到哪些档位资源始终由 3.1 / 3.2 按等级决定（`visibleVisibilities(level)`）。所以给 L1 开 `download` 之后，他能下载的是自己**看得见**的 `public` / `member` 档原图，`admin` 档仍然看不见（404）、他人的 `private` 也看不见（D1）——**要让他进更高的档位，请调级，不要开功能位**。

**三态与落库**：每个能力位对每个人有三种状态 —— `跟随等级`（默认，不落库）/ `强制开` / `强制关`。落库为 `users.feature_grants` 一列 JSON，形如 `{"download":1,"zip":1,"editAny":0}`，**缺键即跟随等级**，不新增权限表（与 D20 同口径，见 19 章）。

**判定顺序**（补进 7.1，7.2 的矩阵因此变成「默认值来源」而不是终局）：

```
1. 档位可见性       按 3.1 / 3.2 与 level 判定 → 不可见一律 404（反枚举，不变）
2. 有效能力位       level 默认值经 feature_grants 覆盖 → 该位为关 → 403 CAP_DISABLED
                    该位为开 → 跳过等级默认值的动作禁止（403 LEVEL_FORBIDDEN 不再触发）
3. 归属范围         editAny 决定 own / any，仍按 7.2（403 NOT_OWNER）
4. 身份特有闸门     临时账号的 7.3 开关与白名单、分享链接的 4.4 绕过范围、账号 disabled
```

- **收紧一定拦得住**：`强制关` 优先于等级默认值，L4 自己给自己关也拦。
- **放开只放动作**：`强制开` 不越过上面第 1 步的档位可见性，也不越过 12 章任何安全约束，还不改变 4.4「`admin`/`private` 相册禁止建链」这类资源自身的闸门。
- 关掉的能力位对应的 8.4 宫格**不渲染**（与 ❌ 同处理，不是置灰），格数随之减少，列数按 8.5 的格数规则重算；直接敲 URL 或调接口回 **403**（功能存在、只是他没有，与 404 的「看不见」区分开，见 7.2 补充 1）。

**防锁死与保留位**：`writeSiteSettings` 不可开给 L1–L3（409 `CAP_RESERVED`，站点核心配置只归超管，同 6.1 与 10.5）；唯一在职 L4 的 `adminConsole` 与 `writeSiteSettings` 不可设为关（409 `LAST_SUPER_ADMIN`，否则再没人能进后台改配置，与 12.4 的「不可降级 / 不可禁用唯一超管」同一条防线）。账号被 `disabled` 时能力位一律视为全关（6.1 现状）。

**谁能改、怎么生效**：只有 L4（包括改他自己），L3 调用一律 403 `LEVEL_FORBIDDEN` 且后台不渲染入口。能力位**不进 JWT**——守卫每次请求按 `uid` 现取（真接口用 Redis 缓存，TTL ≤ 60 秒），所以改完最迟 60 秒全站生效，不用等他重新登录。改动写 `logs(action='user_feature_grant')`，`detail` 逐键记 `cap=mode` 与目标 uid；被覆盖的项在 `GET /auth/me` 与后台成员行里回显 `capsOverridden`，让本人和管理者都知道这一位不是默认值（D9 的 `overridden[]` 同范式）。超管转让后覆盖记录仍挂在原 `uid` 上，不随等级变化重算。

**不适用对象**：临时账号本来就是逐项开关制（6.2 五开关 + D9 降权表），改它的开关走 10.5 的 temp-accounts 接口，不在本节范围内；游客无账号。

**与 D20 的分工**（两条轴，别混）：`drive_perm1~4` 决定**能不能进某个用途的目录**（工作室 / 管理 / 个人共享 / 私人，见 5.4 规则 2/4/5/6），`download`、`delete` 等能力位决定**能对这个目录里的东西做什么**。网盘里的一次下载要同时过目录档闸门与 `download` 能力位，**AND**，任一不过即拒。垃圾箱（规则 12）与爬虫（规则 11）两条轴都不参与，仍只有 L4 能进。

## 7. 权限校验决策表（替换 V1.0 第 8 节）

所有资源访问与操作接口必须先过统一守卫（NestJS `Guard` + 资源级 `PermissionService`），按下表判定，任一环节不通过即写 `logs(result=0)` 并返回。

### 7.1 身份识别顺序

```
1. 请求带 share_token          → 走分享链接分支（4.4），跳过通用档位判定
2. 解析 JWT：type=temp         → 临时账号分支（7.3）
3. 解析 JWT：type=user         → 按 level 分支（7.2）
   3a. 档位可见性             → 按 3.1 / 3.2 与 level，不可见一律 404（不看个人授权）
   3b. 有效能力位             → level 默认值经 `users.feature_grants` 覆盖后判动作（6.4，D21）
                                关 → 403 CAP_DISABLED；开 → 不因等级默认值禁止而拦截
4. 无凭证                       → 游客分支
```

### 7.2 正式成员：操作 × 档位矩阵

| 操作 | public | member | admin | private（他人） | private（本人） |
|---|---|---|---|---|---|
| 预览 L1 | ✅ | ✅ | ❌ | ❌ | ✅ |
| 下载原图 / 打包 L1 | ❌ | ❌ | ❌ | ❌ | ❌（需 L2+ 代下） |
| 预览 L2 | ✅ | ✅ | ❌ | ❌ | ✅ |
| 下载 L2 | ✅ | ✅ | ❌ | ❌ | ✅ |
| 编辑标签 / 重命名 L2 | 仅自有 | 仅自有 | ❌ | ❌ | ✅ |
| 删除 / 批量 L2 | 仅自有 | 仅自有 | ❌ | ❌ | ✅ |
| 生成分享链接 L2 | 自有图片 | 自有图片 | ❌ | ❌ | ✅ |
| 上传 L2 | ✅ | ✅ | ❌ | 建档即 private ✅ | ✅ |
| 预览 L3 | ✅ | ✅ | ✅ | ❌ | ✅ |
| 编辑 / 删除 / 批量 L3 | ✅ | ✅ | ✅ | ❌ | ✅ |
| 改他人资源权限 L3 | ✅ | ✅ | ✅ | ❌ | ✅ |
| 生成任意分享链接 L3 | ✅ | ✅ | ✅ | ❌ | ❌ |
| 全部操作 L4 | ✅ | ✅ | ✅ | ✅ | ✅ |

> L4 全放行，无拦截。表中「仅自有」= `resource.upload_uid == 当前 uid`。L1 无编辑他人、无删除、无下载、无链接、无批量。
>
> **V1.2 补充**：新增的 `Action.TaskStageUpdate`（推进返图修图阶段）**不落在档位维度上**，而落在工单归属（`owner_uid`）与等级上，因此不在本表出现，判定规则单列于 17.4。工单所指向资源的可见性仍按本表判定。
>
> **D21 的定位**：本表现在是**能力位的等级默认值来源**，不再是终局判定——L4 可对单个人把 6.4 的 11 个能力位逐项改成「强制开 / 强制关」，守卫按覆盖后的有效能力位判动作（`decide()` 的第 2 步）。落到本表上的效果是：`download` `zip` `upload` `delete` `changeVisibility` `shareLink` `canSetPublic` 各自对应一行，`editAny` 决定「仅自有」还是全站（即表中「仅自有」这一列语义的开关），`adminConsole` / `writeSiteSettings` 对应 8.2 与 10.5 的后台入口。**「仅自有」= `resource.upload_uid == 当前 uid` 这条归属判定不受个人授权影响**，只有 `editAny` 能把它放宽到全站。三态拒绝的码位分工：档位不可见 → 404；能力位被关 → 403 `CAP_DISABLED`；能力位有但归属不是本人 → 403 `NOT_OWNER`。
>
> 两点判定补充（开发已按此实现并有单测锚定）：
> 1. ❌ 有两种成因：**档位不可见**（如 L3 看他人 private）返回 **404**，不暴露资源存在性；**可见但动作被禁**（如 L1 下载自有图）返回 **403**。
> 2. 「他人」列指非本人上传的资源；**本人上传的 private 资源始终可由本人自管档位**（否则私有相册建完就再也发不出去），L1 额外受「不可设为 public」限制，见 6.1 与 `canSetVisibility`。

### 7.3 临时账号判定顺序

```
1. disabled=1 或 expire_time < now         → 401，永久失效
2. 资源是否命中 access_albums/folders 白名单 → 未命中即 404（不暴露存在性）
3. 结构性禁止：重命名/改元数据、删除、改权限、生成分享链接、
   任何后台管理与用户列表                    → 一律 403（TEMP_FORBIDDEN，与开关无关）
   ※ 必须排在开关检查之前，否则会被误报成「开关没开」，诱导管理员去开一个开不了的开关
4. 按操作查开关（开关与白名单是 AND 关系，缺一不可）：
   预览 → allow_preview
   下载原图/原文件、ZIP → allow_download
   上传图片 → allow_upload_img（目标相册须命中白名单）
   上传文件 → allow_upload_file（目标文件夹须命中白名单）
   编辑标签 → allow_edit_tag，且仅限本人本次上传的资源（upload_temp_id = 本账号）
5. 配额：已用满 space_quota 时上传 → 413；
   `used_space + 待传字节 > space_quota` 的精确判定在上传服务内完成（守卫层拿不到待传大小）
6. 命中即放行；上传落库 upload_uid = owner_uid、upload_temp_id = temp.id
```

开关与白名单是 **AND** 关系，缺一不可。

### 7.4 游客判定

```
公开档位资源的预览                          → 放行，只回预览图/缩略图 URL
非 public 资源                              → 404
网盘任何路径（含 public 文件夹）            → 401（网盘整体需登录，引导登录而非报无权限）
公开资源的下载/上传/编辑/删除/批量/后台     → 403（已可见，纯属动作被禁）
持有有效 share_token                        → 走 4.4 例外分支
```

> 401 与 403 的分工：**容器级隔离**（登录才能进）用 401，**动作级禁止**（看得见但不给做）用 403。
> 前端据此决定是否弹登录框——对公开图的下载请求弹登录框是错的。

**存储目录约定**

```
/data/piks/
  originals/YYYY/MM/<uuid>.<ext>     原图/原文件，无 Web 可达路径
  derived/preview/<image_id>.webp
  derived/thumb/<image_id>.webp
  tmp/chunk/<upload_id>/<index>       分片碎片，24h 清理
```

文件名一律重命名为 UUID，**原始名仅存 DB**，杜绝路径穿越（`../`）与同名覆盖。下载时通过 `Content-Disposition` 回填原始名（需 RFC 5987 编码，中文文件名易踩坑）。

### 10.7 加密空间（新增，D26，详见 5.7）

**没有 `/vault/unlock`**——口令对不对只在浏览器里靠「本地能否解开校验子」判定，因此这一组接口里**不存在任何携带口令的请求**；下列接口全部要求成员身份（`meta.auth + meta.member`），游客 401、临时账号 403。

| 方法 | 路径 | 权限 / 语义 |
|---|---|---|
| GET | `/vault/status?owner=` | 本人的空间状态与派生参数（`initialized` `salt` `iterations` `verifier` `hint` 条数与密文/明文体积、配额）。`owner` **仅 L4** 可带，指向他人时返回同一份汇总并写 `logs(action='vault_admin_view')`；L1–L3 带他人 `owner` → **404**（不泄露存在性，D1） |
| GET | `/vault/files?owner=` | 条目列表。**本人**行含 `nameCipher` 与 `links.cipher`；**他人**行两者一律 `null`，`canDelete` 对 L4 为 `true`——即「看得到有 N 条、占多少体积、可以删，但解不开也不给素材」 |
| GET | `/vault/spaces` | **仅 L4** 的成员加密空间总览，逐人列「是否已初始化 / 条数 / 密文体积 / 配额」，无任何内容字段；L1–L3 → 403 `LEVEL_FORBIDDEN` |
| POST | `/vault/setup` | 首次设口令：落 `{ salt, iterations, verifier, hint? }`，**body 里没有口令**；`iterations < 10000` 或缺字段 → 400；已初始化 → 409 `VAULT_EXISTS`（要换口令走 rekey）。写 `logs(action='vault_setup')` |
| POST | `/vault/rekey` | 改口令 = **一次请求带走新参数 + 整空间重封好的密文**（`files[]: { id, nameCipher, cipherSize, cipher }`）。两趟处理：整份校验通过后才提交、**参数最后一步才换**。条目数与实际不符 → 409 `REKEY_SET_MISMATCH`；容器长度与 `cipherSize` 不符 → 400 `CIPHER_SIZE_MISMATCH`；重封后超配额 → 413 `QUOTA_EXCEEDED`；未初始化 → 409 `VAULT_NOT_INITIALIZED` |
| POST | `/vault/files` | 建条目：元数据 `{ nameCipher, plainSize, cipherSize, mimeType, ext }` + 密文。mock 把 base64 密文混在同一份 JSON 里一次提交；真接口先建条目再返回 `links.cipher`，由前端 `PUT` 裸字节。校验：容器非法 400 `CIPHER_MALFORMED`、体积不符 400 `CIPHER_SIZE_MISMATCH`、**5.2 黑名单扩展名 415 `EXTENSION_BLOCKED`**、超过 `vault.max_file_size` 413 `FILE_TOO_LARGE`、配额不足 413 `QUOTA_EXCEEDED` |
| PUT | `/vault/files/:id/cipher` | （真接口才有）提交密文字节 `application/octet-stream`，**不走 5.3 的分片会话**（明文永不出页，无可切块的东西） |
| GET | `/vault/files/:id/cipher` | 取回密文容器，**仅归属人本人**；非本人（含 L4）→ 404。这是 5.7「不给超管留下离线爆破素材」那条边界的接口级落点 |
| DELETE | `/vault/files/:id` | 就地销毁、**不进垃圾箱**，返回 `{ id, purged: true }`，配额同步归还。归属人本人与 L4 可为；其余 → 404。写 `logs(action='vault_delete')`，`detail` 只有密文体积 |
| POST | `/vault/destroy` | **忘记口令的唯一出路**：清空本人全部密文与派生参数，回到未初始化状态，返回 `{ uid, purged }`。需前端打字确认「销毁」；不可逆、无还原。写 `logs(action='vault_destroy')` |

## 12. 安全开发约束（强制落地）

1. **密码**：bcrypt(cost 12)，禁止明文 / 简单哈希。临时账号密码、分享链接密码同样 bcrypt
2. **路径安全**：上传文件重命名为 UUID 存储，原始名不参与任何文件系统路径拼接；存储根目录与代码目录物理隔离且在 web root 之外
3. **禁止直连原图**：所有图片与文件字节必须经鉴权接口输出，`originals/` 不允许任何静态路由。预览接口与下载接口分离
4. **真实类型校验**：magic bytes 判定，不信任扩展名与客户端 `Content-Type`；`.svg` 默认拒（XSS 载体）
5. **越权防护**：所有 `:id` 参数必须走资源级校验，禁止仅凭前端传来的 ID 直接查库返回；无权与不存在统一返回 `404`，不用 `403` 泄露存在性
6. **Token 生命周期**：成员 JWT 15 分钟 + refresh，临时账号 JWT 15 分钟且受 `expire_time` 双闸门；登出与销毁写入 Redis 黑名单。分享链接过期后永久失效
7. **限流**：登录 5 次/分/IP + 账号锁定 15 分钟；上传接口按配置限流；分享链接访问 60 次/分/IP，防枚举
8. **游客隔离**：只返回压缩预览图，接口响应体内不得包含 `original_path`、上传账号、`status` 标签、其他 coser 名
9. **敏感信息**：`config` 走环境变量，DB 口令与 Redis 口令不入代码库；`.env` 加入 `.gitignore`
10. **CSRF / 点击劫持**：Cookie 会话（分享链接解锁）设 `SameSite=Lax`；全站 `X-Frame-Options: DENY`、`CSP` 限制图片来源
11. **日志脱敏**：`logs.detail` 不得写入密码、token 全文；密码字段在所有 API 响应中排除（实体列标记 `select: false`）
12. **导出安全**：审计日志 CSV 导出需转义公式注入前缀（`= + - @`）
13. **依赖审计**：CI 跑 `npm audit` / `pnpm audit`，高危阻断合并

### 12.4 超管唯一性

V1.0 说 L4「不可被任何账号删除、降级」，但若存在两个 L4，该条会互相死锁。V1.1 定为：**系统仅允许存在 1 个 L4**。变更超管需当前 L4 主动转让（同一事务内降级自己 + 升级对方），转让要求二次确认。若需要多超管，请显式告知，届时该条款改写为「L4 之间不得互相操作，且至少保留 1 名在职 L4」。

## 17. 返图修图任务流转（V1.2 新增）

### 17.1 这是缺失的模块，不是缺失的页面

原型图 5（账号列表）与图 6（任务列表）的整个信息架构都围绕「前期修图 / 后期返图」两阶段的完成度组织，而 V1.1 全文没有任何一处提到它：没有表、没有状态字段、没有接口，7.2 矩阵里也没有对应操作行。补不出来，第 8 章这两页就无法实现，所以单独立章。

### 17.2 工单宿主与阶段定义

**宿主**：`temp_accounts`（D10 —— 一个临时账号 = 一条返图工单，不新建 1:1 表）。

| 阶段 | 字段 | 业务含义 | 取值 |
|---|---|---|---|
| 前期修图 | `pre_stage` | 原图筛选 + 初修（调色、液化、裁剪、去瑕疵） | `0` 未完成 / `1` 已完成 |
| 后期返图 | `post_stage` | 精修成片回传给 coser 并交付 | `0` 未完成 / `1` 已完成 |

配套 `pre_done_time` / `post_done_time`，由后端在状态置 `1` 时盖时间戳，**前端不可传入**。

**状态机**

```
(0,0) 前期修图中 ──pre=1──▶ (1,0) 待后期 ──post=1──▶ (1,1) 全部完成
   ▲                            │                        │
   └────── 回退（仅 L3/L4）──────┴────────────────────────┘
```

1. 正向推进不可跳跃：`post_stage` 只能在同工单 `pre_stage = 1` 之后置 `1`，否则 `409 STAGE_ORDER_VIOLATION`。
2. **回退**（`1 → 0`）仅 L3/L4 可执行，必须带 `reason`（≤ 200 字），写 `logs(action='task_stage_reopened', result=1)`，并把对应 `*_done_time` 置 NULL。
3. 阶段状态与账号有效性解耦：账号到期或被注销后，工单两阶段值**保留不清**，用于事后统计与追责（注销只是 `disabled=1`，不是删行）。
4. 阶段推进不代表资源交付完成，也不作为生成分享链接的前置条件（4.4 未要求）；工单详情页只提供「一键生成本人返图链接」入口，仍走 `Action.CreateShareLink` 判定。

### 17.3 列表查询语义（原型图 6 的筛选条）

| 筛选值 | 确切条件 | 说明 |
|---|---|---|
| 前期未完成 | `pre_stage = 0` | 含 (0,0) |
| 后期未完成 | `pre_stage = 1 AND post_stage = 0` | **取「真正卡在后期这一步」**，不含前期都没完成的工单；若你要的是「凡 post=0 都算」，此处改成 `post_stage = 0` 即可，其余不受影响 |
| 前期已完成 | `pre_stage = 1` | 含 (1,0) 与 (1,1) |
| 后期已完成 | `post_stage = 1` | 等价 (1,1) |
| 全部已完成 | `pre_stage = 1 AND post_stage = 1` | |

- 默认视图排除已注销工单（`disabled = 0`），注销项按 D11 作为行操作而非筛选值。
- 搜索 `q`：对 `account_no` / `login_name` / `display_name` 做**前缀**匹配（`LIKE 'q%'` 可用索引），不做 `%q%` 全表扫；输入 ≥ 2 字符才发请求。
- 排序：`by ∈ {create_time, pre_done_time, post_done_time}`，`sort ∈ {asc, desc}`（图 6 的「递增」= asc），默认 `create_time desc`。
- 分页 `{page, pageSize ∈ 20|50|100, total, list}`，走全局响应信封。
- 复合索引 `idx_stage_query (disabled, pre_stage, post_stage, create_time)`，见 11.2。
