## 1. 项目定位

面向 Cos 摄影工作室 / 社团摄影团队的专属 Web 平台，整合两条业务线：

1. **漫展标签化返图交付** — 现场传图 → 打标签 → 筛选 → 按 coser 单人精准交付。
2. **多级权限文件共享网盘** — 后期工作文件沉淀、团队共享、外聘人员临时协作。

三种身份共用一套资源权限模型：四级正式成员、临时账号、游客。

核心能力清单：四级精细化成员权限、自定义临时账号/限时链接、无登录游客只读模式、多标签返图系统、树形目录网盘、操作日志审计、资源权限管控与安全防护。

## 3. 全局规则与通用定义

### 3.1 资源可见范围

相册、图片、文件夹、文件四类资源共用同一套枚举，**严格度递增**：

`public（公开）` < `member（成员可见）` < `admin（仅管理员）` < `private（私有）`

> 注：V1.0 表述为「权限优先级 私有 > 仅管理员 > 成员可见 > 公开」易被误读为「多规则冲突时取私有」。此处明确：该顺序是**严格度序**，用于计算继承上限（见 3.2），不是冲突仲裁序。单个资源永远只有一个 `visibility` 值。

| 档位 | 可访问主体 | 原图 / 原文件下载 |
|---|---|---|
| `public` | 游客 + 临时账号 + 全部正式成员 | 游客与临时账号默认禁止；L1 禁止；L2/L3/L4 允许 |
| `member` | 仅 L1–L4 正式成员 | L1 禁止；L2/L3/L4 允许 |
| `admin` | 仅 L3、L4 | L1 无预览权；L3/L4 允许下载 |
| `private` | **仅资源归属人本人 + L4 超管** | 归属人与 L4 允许 |

### 3.2 继承上限规则（新增，D3）

资源的有效可见范围 = `max(自身 visibility, 父容器 visibility)`（按 3.1 严格度序取更严的一档）。

- 图片必须满足 `rank(image.visibility) >= rank(album.visibility)`
- 文件夹与文件必须满足 `rank(自身) >= rank(祖先链上任一节点)`
- **写入时校验**：子资源试图设得比父容器更宽松 → 返回 `409`，提示「需先放宽上级 {相册|文件夹} 的权限」
- **父容器放宽时**：不自动传染子资源。管理员把相册 `member → public`，若相册内存在 `member` 图片，系统弹窗要求二选一：①「同步放宽全部子资源到 public」②「仅放宽相册本身，内部图片保持 member」（此时游客只见相册壳，不见图）
- 私有资源不参与任何列表聚合，仅在归属人自己的「个人中心」和 L4 的全站视图里出现

### 3.3 三类身份

| 身份 | 来源 | 会话载体 | 后台可见性 |
|---|---|---|---|
| 四级正式成员 | 后台手动创建（无注册入口） | JWT，含 `uid` + `level` | 是 |
| 临时账号 | 仅 L3/L4 创建 | JWT（含 `temp_id`）或凭 `access_token` 直连 | 是，独立列表 |
| 游客 | 匿名访问 | 无 | 否 |

三类身份权限完全隔离，不存在继承或叠加。一个会话只能是其中一种。

## 4. 漫展标签返图系统（核心业务）

### 4.1 标签体系

五大类型，图片与标签多对多，支持双人 cos / 多角色同框：

| 类型 | 语义 | 示例 | 谁可增删改 |
|---|---|---|---|
| `event` | 漫展 | `2026-09 本地次元漫展` | L2+ 输入即建（自动去重） |
| `coser` | Coser 昵称，**核心交付标签** | `柚子` | L2+ 输入即建 |
| `role` | 作品-角色 | `原神-雷电将军` | L2+ 输入即建 |
| `photographer` | 拍摄者 | `阿哲` | L2+ 输入即建 |
| `status` | 内部状态：待修 / 已修 / 废弃 | `待修` | **仅 L3/L4 可增删标签本身**；成员可给自有图片打已有状态 |

规则：
- 输入框自动补全，命中 `tag_name` 与 `alias`，杜绝重复标签（DB 层 `UNIQUE(tag_type, tag_name)` 兜底）
- 同一图片在同一 `tag_type` 下允许多个标签（多角色场景）
- **`status` 标签对外一律不下发**：游客接口、分享链接接口、临时账号接口返回的 tags 数组均需过滤 `tag_type='status'`
- 标签合并：`tags.merged_into` 指向目标标签，历史关联由任务迁移后停用原标签，不物理删（保留频次统计）

### 4.2 相册管理

一个相册对应一场漫展。字段：名称、漫展名称、漫展日期、地点、简介、封面图、可见范围、状态、创建人。

- 状态三值：`1 正常` / `2 归档`（前台不展示，成员可查）/ `3 锁定`（禁止上传、编辑、改标签，仅可浏览与下载）
- 创建相册即绑定 `visibility`，成员默认只能建 `member` 或 `private`
- 封面替换从相册内已有图片选取；删除封面图时应用层清空 `cover_img_id`（该列刻意无外键，避免与 `images.album_id` 循环引用）
- 删除相册为**物理删除并级联删除全部图片**，不可恢复 → 前端二次确认（要求输入相册名），后端写 `logs`
- 权限：`private` 相册对 L3 完全不可见（D1）

### 4.3 图片上传

- 批量拖拽上传，移动端适配（漫展现场手机直传）
- 走分片上传通道（见 5.3），小图（< 5MB）单请求直传
- 原图与预览图**分目录独立存储**，二者访问路径均不可直接静态访问
- 自动生成三种产物：原图（无损保留）、预览图（长边 2048px）、缩略图（宽 400px）
- **自动读取 EXIF `DateTimeOriginal`** 写入 `images.shot_time`；无 EXIF（截图 / 后期图）则留空，由上传者在详情页补填
- RAW 格式（`.cr2/.nef/.arw/.raw`）允许上传存档，但后端无法生成预览 → 缩略图用嵌入 JPEG 预览回退，失败则占位图
- 水印：按站点配置决定是否给**预览图与缩略图**叠加（D7），原图永不修改；`watermarked` 标记记录该图生成时是否带水印
- MD5 查重：同归属人已存在相同 MD5 → 返回 `409`「该图片你已上传过」，附已存图片链接，前端允许「仍要上传」（放行后写新记录，文件复用同一路径）
- 上传完成后进入「待打标」态，支持批量绑定标签 + 单张微调

### 4.4 返图筛选与交付

**多维组合筛选**（相册详情页顶部）：漫展、coser、角色、摄影师、图片状态，条件之间为 AND，同类型多值为 OR。筛选走 `image_tag_map` 的 `idx_tag` 反查 + `GROUP BY image_id HAVING COUNT(DISTINCT tag_id)=N`。

**Coser 专属返图分享链接**（核心交付功能）：

配置项 — 有效期、访问密码（可选）、是否允许原图下载、命中方式（动态 / 快照）。

- `snapshot=0`（默认，动态）：访客每次访问时按 `album_id + coser_tag_id` 实时命中，新上传并打上该 coser 标签的图片会自动出现，无需重发链接
- `snapshot=1`（快照）：生成时把当前筛选结果固化进 `share_link_images`，用于筛选条件含角色/摄影师等复合条件的场景（`filter_json` 保存原始条件供追溯）
- **权限绕过范围（D2）**：链接有效期内，访客可见 = 该相册内命中筛选条件的图片预览，**忽略这些图片自身的 `visibility`**，但：
  - 相册 `visibility` 为 `admin` 或 `private` 时**禁止生成链接**（`403`，提示先改为 public/member）
  - 访客只能命中集合内的图片，不可枚举、不可进入相册详情页、不可看到相册内其他任何图片
  - 命中集合外的图片 ID 被请求时返回 `404`（不是 403，避免暴露 ID 存在性）
  - 不下发 `status` 标签，不下发上传者账号信息，不下发其他 coser 名字
- `allow_download=1` 时访客可下载该集合内的**无水印原图**；`=0` 时仅提供预览图 + 带水印
- 密码保护：`password` 存 bcrypt，验证通过后签发 2 小时有效的链接子会话（Cookie，`HttpOnly` + `SameSite=Lax`），绑定 `share_token`
- 过期或被 `revoked` 后永久失效；链接访问计入 `visit_count` 与 `logs`
- L1 与临时账号不可生成链接

### 4.5 批量操作

批量加/移除标签、批量改状态、批量改可见范围、批量重新生成水印、批量打包 ZIP。

- 打包 ZIP：L2/L3/L4 可用；**L1 与游客禁用**；临时账号需 `allow_download=1`
- 单次批量上限 500 张，ZIP 为流式生成（不落临时盘），超时 10 分钟
- 批量改可见范围时必须逐条跑 3.2 继承校验，不合规项列清单返回，不静默跳过
- 批量删除：仅 L2（自有）/ L3 / L4；L1 禁用

### 4.6 标签后台管理（L3/L4）

标签库全量列表、重命名、合并重复标签、删除无效标签、按 `use_count` 排序统计与清理冗余。`status` 类型标签为内置，仅允许改文案不允许删。

## 5. 文件共享网盘模块

### 5.1 定位

独立于返图相册的第二存储域，存后期源文件、预设、合同、素材、样片等。树形多级目录，每个文件夹独立配权。

### 5.2 文件类型

白名单由 `site_settings.upload.file_extensions` 配置，默认允许：图片、PDF、Word/Excel/PPT、PSD、AI、ZIP/7Z/RAR、MP4/MOV、预设文件。

**扩展名白名单 + 二进制头校验双重把关**：用 `file-type` 读 magic bytes，实际类型不在白名单一律拒收；黑名单（`.exe/.bat/.sh/.msi/.dll/.apk/.jar/.js/.vbs/.ps1/.scr`）无条件拒绝，即使命中图片白名单也拒。`mime_type` 落库存**校验后的真实类型**，不信任客户端上报的 Content-Type。

### 5.3 核心功能

- **树形目录**：`folders.path` 物化路径（`/1/5/12/`）+ `depth`，最大 8 层，取子树走 `path LIKE '/1/5/%'` 命中 `idx_path`，避免递归查询。同级重名由 `UNIQUE(parent_id, name)` 约束（注意 MySQL 允许 `parent_id` 为 NULL 时重复，**顶级目录重名需在应用层额外校验**）
- **文件夹移动**：需重算整棵子树的 `path` 与 `depth`（单事务内批量 UPDATE），并禁止移动到自身子孙下（防环，校验 `target.path` 不以 `moving.path` 开头）
- **断点续传**：客户端分片（默认 5MB）→ `upload_sessions` 记录已收分片下标 → 刷新/断网后凭 `upload_id` 拉取缺失分片续传 → 全片齐后服务端顺序合并、算 MD5 与 `md5_client` 比对 → 建 `files` 记录。会话 24 小时过期，未合并碎片由定时任务清理
- **在线预览**：图片直出、PDF 用浏览器原生渲染、MP4 走 HTTP `Range` 分片响应（支持拖动进度条）。PSD/AI 仅给缩略图，不承诺完整渲染
- **元数据**：文件名、大小、真实 MIME、MD5、上传人、上传时间
- **下载**：单文件直下、多文件流式 ZIP、分享链接生成（可设有效期 + 密码 + 允许下载次数）
- **空间配额**：见 5.6

### 5.4 权限控制

完全复用全局权限模型与 3.2 继承上限规则。游客禁止访问一切网盘资源（分享链接通道除外）。L1 可预览 `public`/`member` 文件，但禁止下载与打包。

### 5.5 临时账号的网盘授权（新增）

`temp_account_folders` 白名单授权**级联包含该文件夹的全部子孙**（因为子资源可见性受祖先约束，授权父目录即授权其内容）。有效权限 = 白名单命中 ∧ `allow_preview` / `allow_download` / `allow_upload_file` 各开关。

### 5.6 存储空间配额（新增，明确语义）

- `space_quota`：`0` = 不限；正数为字节上限
- `used_space`：实时累计，计入该用户名下**全部** images.file_size 与 files.file_size（含 `private`）
- 更新时机：上传成功建记录时 `+file_size`，删除资源时 `-file_size`，必须在同一事务内，否则配额失真
- 校验：上传前比较 `used + 待传大小 <= quota`，超限返回 `413`，前端提示「空间不足，已用 X/Y」
- **预览图与缩略图的体积不计入配额**（配额按原图/原文件计），但后台仪表盘单独统计衍生副本占用，供容量告警
- L4 在用户管理页可改配额；临时账号有独立 `space_quota`，不占用 owner 的配额

## 6. 用户权限体系

### 6.1 四级正式成员

**L4 超级管理员**
- 全站配置：站点参数、水印配置、上传限制、文件白名单、存储配置
- 用户管理：增删改、禁用、重置密码、调整等级、配置空间配额（对 L1–L3 全部可操作）
- 资源管理：所有相册、图片、文件夹、文件，可删除任意资源
- 临时账号：创建、销毁、管理全部
- 日志审计：全站所有操作记录
- 访问 `private` 资源（唯一可查看他人私有内容的角色）
- 无任何访问 / 上传 / 下载 / 操作限制
- **不可被删除、不可被降级、不可被禁用**；不可被其他 L4 操作（系统仅允许存在一个 L4，见 12.4）

**L3 普通管理员**
- 成员管理：L1、L2 的新增、禁用、重置密码、调整等级、**配额设置**；无法操作 L4
- 临时账号：创建、销毁、配置各项权限
- 资源管理：审核与管理全站 public/member/admin 三档资源，批量修改其权限；**不可访问他人 private 资源（D1）**
- 上传、下载、编辑 public/member/admin 资源；可编辑他人资源的标签
- 可生成任意 coser 返图分享链接
- 标签库管理、留言审核、日志查看（本人与他人）
- 无权限：修改站点核心配置、删除超管、清空全站数据

**L2 普通成员（摄影师 / 后期正式成员）**
- 自主上传返图与工作文件
- 管理个人上传的全部资源（编辑标签、重命名、移动、删除）
- 预览、下载 public 与 member 的相册及文件；管理自有 private 资源
- 为自有图片添加五类标签（`status` 仅可选已有值）
- 多维筛选返图、生成自有图片的 coser 专属分享链接
- 建相册、归档/锁定自有相册
- 无权限：管理他人账号、修改他人资源、任何后台管理入口

**L1 见习成员（新人 / 实习）**
- 上传个人返图与工作文件，自主编辑个人资源标签
- 预览所有 public 与 member 资源
- **禁止**：一切原图 / 原文件下载、ZIP 打包下载
- **禁止**：删除任何图片与文件（**含个人上传**）、删除相册与文件夹
- **禁止**：生成 coser 返图分享链接、任何批量操作
- **禁止**：创建相册？—— V1.0 未写明，V1.1 定为**可以创建相册**（否则无法上传返图），但其相册不可设为 public（对外发布需 L2+）
- 无任何用户管理、后台配置权限

### 6.2 临时账号体系

**适用**：漫展现场外聘摄影师、合作 coser、临时后勤，短期协作，免注册，到期自动失效。
**创建主体**：仅 L3、L4。

配置项：

| 配置 | 说明 |
|---|---|
| 访问方式 | ①`login_name` + `password` 登录页登录；②`access_token` 一次性专属链接直连（可叠加 `password` 验证）。**至少配一种**，两者皆空则创建失败 |
| 有效时长 | 自定义起止，1 小时 ~ 30 天，`expire_time` 到期自动失效 |
| 资源白名单 | `temp_account_albums`（相册级，含其内全部图片）+ `temp_account_folders`（文件夹级，含全部子孙）。白名单为空 = 无任何资源访问权，仅可上传到指定投递目标 |
| 权限开关 | `allow_preview` / `allow_download` / `allow_upload_img` / `allow_upload_file` / `allow_edit_tag` |
| 空间配额 | `space_quota`，独立于 owner |
| 归属人 | `owner_uid` = 创建该账号的管理员 |

核心规则：
- 无后台管理权限、无法查看用户列表、无法修改站点配置、无法生成分享链接
- **上传资源自动归属工作室**：写入 `upload_uid = temp_accounts.owner_uid`、`upload_temp_id = temp.id`，账号到期后资源永久保留（外键 `ON DELETE SET NULL` 只清身份标记，不清资源）
- 管理员可提前手动销毁（`disabled=1`，立即失效，已签发的 JWT 靠 15 分钟短 TTL + Redis 黑名单兜底）
- 失效账号无法登录、无法访问任何资源，历史访问日志保留
- 临时账号可访问范围内，`private`/`admin` 资源仍需白名单显式命中才可见（白名单即授权，可覆盖档位），但 `status` 标签一律不下发

### 6.3 游客模式

- 无需注册登录，直接访问前台
- 仅可浏览 `public` 相册的预览图（且图片自身也为 `public`）
- 禁止访问全部网盘资源、禁止查看 member/admin/private 资源
- 禁止原图下载、文件下载、任何上传操作
- 隐藏内部状态标签，仅展示漫展与角色标签
- 首页相册列表按 `visibility='public' AND status=1` 过滤
- **唯一例外**：持有有效 coser 分享链接时，按 4.4 的绕过规则访问命中集合
- 游客留言（可选功能，由 `guest.comment_enabled` 开关）：需 L3/L4 审核通过后才公开展示，`contact` 字段仅管理员可见

## 7. 权限校验决策表（替换 V1.0 第 8 节）

所有资源访问与操作接口必须先过统一守卫（NestJS `Guard` + 资源级 `PermissionService`），按下表判定，任一环节不通过即写 `logs(result=0)` 并返回。

### 7.1 身份识别顺序

```
1. 请求带 share_token          → 走分享链接分支（4.4），跳过通用档位判定
2. 解析 JWT：type=temp         → 临时账号分支（7.3）
3. 解析 JWT：type=user         → 按 level 分支（7.2）
4. 无凭证                       → 游客分支
```

### 7.2 正式成员：操作 × 档位矩阵

| 操作 | public | member | admin | private（他人） | private（本人） |
|---|---|---|---|---|---|
| 预览 L1 | ✅ | ✅ | ❌ | ❌ | ✅ |
| 下载原图 / 打包 L1 | ❌ | ❌ | ❌ | ❌ | ❌（需 L2+ 代下） |
| 预览 L2 | ✅ | ✅ | ❌ | ❌ | ✅ |
| 下载 L2 | ✅ | ✅ | ❌ | ❌ | ✅ |
| 编辑标签 / 重命名 L2 | 仅自有 | 仅自有 | ❌ | ❌ | ✅ |
| 删除 / 批量 L2 | 仅自有 | 仅自有 | ❌ | ❌ | ✅ |
| 生成分享链接 L2 | 自有图片 | 自有图片 | ❌ | ❌ | ✅ |
| 上传 L2 | ✅ | ✅ | ❌ | 建档即 private ✅ | ✅ |
| 预览 L3 | ✅ | ✅ | ✅ | ❌ | ✅ |
| 编辑 / 删除 / 批量 L3 | ✅ | ✅ | ✅ | ❌ | ✅ |
| 改他人资源权限 L3 | ✅ | ✅ | ✅ | ❌ | ✅ |
| 生成任意分享链接 L3 | ✅ | ✅ | ✅ | ❌ | ❌ |
| 全部操作 L4 | ✅ | ✅ | ✅ | ✅ | ✅ |

> L4 全放行，无拦截。表中「仅自有」= `resource.upload_uid == 当前 uid`。L1 无编辑他人、无删除、无下载、无链接、无批量。
>
> 两点判定补充（开发已按此实现并有单测锚定）：
> 1. ❌ 有两种成因：**档位不可见**（如 L3 看他人 private）返回 **404**，不暴露资源存在性；**可见但动作被禁**（如 L1 下载自有图）返回 **403**。
> 2. 「他人」列指非本人上传的资源；**本人上传的 private 资源始终可由本人自管档位**（否则私有相册建完就再也发不出去），L1 额外受「不可设为 public」限制，见 6.1 与 `canSetVisibility`。

### 7.3 临时账号判定顺序

```
1. disabled=1 或 expire_time < now         → 401，永久失效
2. 资源是否命中 access_albums/folders 白名单 → 未命中即 404（不暴露存在性）
3. 结构性禁止：重命名/改元数据、删除、改权限、生成分享链接、
   任何后台管理与用户列表                    → 一律 403（TEMP_FORBIDDEN，与开关无关）
   ※ 必须排在开关检查之前，否则会被误报成「开关没开」，诱导管理员去开一个开不了的开关
4. 按操作查开关（开关与白名单是 AND 关系，缺一不可）：
   预览 → allow_preview
   下载原图/原文件、ZIP → allow_download
   上传图片 → allow_upload_img（目标相册须命中白名单）
   上传文件 → allow_upload_file（目标文件夹须命中白名单）
   编辑标签 → allow_edit_tag，且仅限本人本次上传的资源（upload_temp_id = 本账号）
5. 配额：已用满 space_quota 时上传 → 413；
   `used_space + 待传字节 > space_quota` 的精确判定在上传服务内完成（守卫层拿不到待传大小）
6. 命中即放行；上传落库 upload_uid = owner_uid、upload_temp_id = temp.id
```

开关与白名单是 **AND** 关系，缺一不可。

### 7.4 游客判定

```
公开档位资源的预览                          → 放行，只回预览图/缩略图 URL
非 public 资源                              → 404
网盘任何路径（含 public 文件夹）            → 401（网盘整体需登录，引导登录而非报无权限）
公开资源的下载/上传/编辑/删除/批量/后台     → 403（已可见，纯属动作被禁）
持有有效 share_token                        → 走 4.4 例外分支
```

> 401 与 403 的分工：**容器级隔离**（登录才能进）用 401，**动作级禁止**（看得见但不给做）用 403。
> 前端据此决定是否弹登录框——对公开图的下载请求弹登录框是错的。

- **用户管理**：四级成员增删改禁用、重置密码、调整等级、配额设置；临时账号创建/销毁/权限配置/到期列表

- **站点设置**：上传限制、文件白名单、水印配置、存储与配额默认值、留言开关、限流参数

> V1.0 未列「留言审核」与「分享链接管理」两个页面，V1.1 补齐，否则对应功能无处落地。

## 9. 技术选型（NestJS + Vue 3）

| 层 | 选型 | 说明 |
|---|---|---|
| 运行时 | Node.js 20 LTS | 单进程 cluster，或 PM2 托管 |
| 后端框架 | NestJS 10 | Module 划分：auth / users / temp-accounts / albums / images / tags / share / drive / settings / logs / guestbook / queue |
| ORM | TypeORM 0.3 | 与 `schema.sql` 对齐，实体即表；`synchronize=false`，一律走 migration |
| 数据库 | MySQL 8.0 | `utf8mb4_0900_ai_ci` |
| 缓存 / 队列 | Redis 7 | BullMQ（预览生成、ZIP 打包、MD5 计算、过期清理）、JWT 黑名单、上传进度、限流计数 |
| 认证 | `@nestjs/jwt` + `passport-jwt` | 三类主体三类 payload；bcrypt(cost 12) |
| 限流 | `@nestjs/throttler` + Redis storage | 登录 5/分/IP，上传接口按 `rate_limit` 配置 |
| 图片处理 | `sharp` | 预览、缩略、EXIF 读取、水印 composite；libvips 内含，无需外部依赖 |
| EXIF | `exifr` | 读 `DateTimeOriginal` |
| 类型探测 | `file-type` | magic bytes 校验，不信任扩展名 |
| 上传协议 | `tus-node-server` | 标准断点续传，与 `upload_sessions` 映射 |
| ZIP | `archiver` | 流式打包，直接 pipe 到 Response，不落临时盘 |
| 视频 | `ffmpeg`（可选） | MP4 首帧封面、时长提取；未装则 `preview_status=2` |
| 文件校验 | `class-validator` + `class-transformer` | 全站 DTO |
| 前端 | Vue 3 + Vite + TypeScript + Pinia + Vue Router | 组合式 API，`<script setup>` |
| UI | Element Plus | 移动端响应式，现场传图页单独做移动版布局 |
| 前端上传 | `uppy` | 分片、断点续传、进度、重试 |
| 预览 | `pdf.js`（PDF）+ 原生 `<video>`（MP4）+ `vue-waterfall`/自绘虚拟列表（图片） | 图片列表 > 500 张必须虚拟滚动 |
| 部署 | Nginx 反代 + Node 进程 | **存储目录必须在 web root 之外**，Nginx 不配 static location；一切文件字节流经后端鉴权接口 |

**存储目录约定**

```
/data/piks/
  originals/YYYY/MM/<uuid>.<ext>     原图/原文件，无 Web 可达路径
  derived/preview/<image_id>.webp
  derived/thumb/<image_id>.webp
  tmp/chunk/<upload_id>/<index>       分片碎片，24h 清理
```

文件名一律重命名为 UUID，**原始名仅存 DB**，杜绝路径穿越（`../`）与同名覆盖。下载时通过 `Content-Disposition` 回填原始名（需 RFC 5987 编码，中文文件名易踩坑）。

**必须在应用层（非 DB 层）实现的校验**

1. 3.2 继承上限：DB 无法表达「子枚举不得宽于父行」，全部写入前校验
2. `temp_accounts`：`access_token` 与 `login_name` 至少一种非空
3. 顶级目录（`parent_id IS NULL`）重名：MySQL 唯一索引对 NULL 不去重
4. `used_space` 增减：与资源增删同事务
5. 删除图片后回写 `albums.cover_img_id = NULL`
6. 配额校验、ZIP 打包前的逐条权限复核

## 12. 安全开发约束（强制落地）

1. **密码**：bcrypt(cost 12)，禁止明文 / 简单哈希。临时账号密码、分享链接密码同样 bcrypt
2. **路径安全**：上传文件重命名为 UUID 存储，原始名不参与任何文件系统路径拼接；存储根目录与代码目录物理隔离且在 web root 之外
3. **禁止直连原图**：所有图片与文件字节必须经鉴权接口输出，`originals/` 不允许任何静态路由。预览接口与下载接口分离
4. **真实类型校验**：magic bytes 判定，不信任扩展名与客户端 `Content-Type`；`.svg` 默认拒（XSS 载体）
5. **越权防护**：所有 `:id` 参数必须走资源级校验，禁止仅凭前端传来的 ID 直接查库返回；无权与不存在统一返回 `404`，不用 `403` 泄露存在性
6. **Token 生命周期**：成员 JWT 15 分钟 + refresh，临时账号 JWT 15 分钟且受 `expire_time` 双闸门；登出与销毁写入 Redis 黑名单。分享链接过期后永久失效
7. **限流**：登录 5 次/分/IP + 账号锁定 15 分钟；上传接口按配置限流；分享链接访问 60 次/分/IP，防枚举
8. **游客隔离**：只返回压缩预览图，接口响应体内不得包含 `original_path`、上传账号、`status` 标签、其他 coser 名
9. **敏感信息**：`config` 走环境变量，DB 口令与 Redis 口令不入代码库；`.env` 加入 `.gitignore`
10. **CSRF / 点击劫持**：Cookie 会话（分享链接解锁）设 `SameSite=Lax`；全站 `X-Frame-Options: DENY`、`CSP` 限制图片来源
11. **日志脱敏**：`logs.detail` 不得写入密码、token 全文；密码字段在所有 API 响应中排除（实体列标记 `select: false`）
12. **导出安全**：审计日志 CSV 导出需转义公式注入前缀（`= + - @`）
13. **依赖审计**：CI 跑 `npm audit` / `pnpm audit`，高危阻断合并

### 12.4 超管唯一性

V1.0 说 L4「不可被任何账号删除、降级」，但若存在两个 L4，该条会互相死锁。V1.1 定为：**系统仅允许存在 1 个 L4**。变更超管需当前 L4 主动转让（同一事务内降级自己 + 升级对方），转让要求二次确认。若需要多超管，请显式告知，届时该条款改写为「L4 之间不得互相操作，且至少保留 1 名在职 L4」。

## 15. 测试验收要点（越权用例优先）

1. 游客请求 `/drive/*` → 401；请求 `/images/:id/original`（public 图）→ 403
2. L1 请求任何下载 / 打包 / 删除 / 建链接接口 → 全部 403，且 `logs(result=0)` 有记录
3. L2 修改他人图片标签 → 403；L3 修改 → 200；L2 删除他人图 → 403
4. L3 访问他人 `private` 相册 / 图片 → **404**（D1）；L4 访问 → 200
5. 把 member 相册内的图片设为 public → 409 并提示先放宽相册（D3）
6. 相册由 member 放宽为 public：选「仅放宽相册」后，游客访问该相册内 member 图片 → 404
7. 分享链接访客请求**集合外**图片 ID → 404；相册内其他 coser 的图完全不可见
8. `allow_download=0` 的链接请求 original → 403；`=1` → 200 且下载文件**无水印**（D7）
9. 链接过期瞬间：已解锁 Cookie 再请求 → 401
10. 临时账号 `expire_time` 到点 → 旧 JWT 立刻失效；其历史上传资源仍在且 `upload_uid=owner_uid`
11. 临时账号白名单为空但 `allow_upload_img=1` → 无目标可传，接口按 7.3 第 2 步回 **404**（未命中白名单一律不暴露存在性，与用例 7 同口径）
12. 伪装 `.jpg` 的 `.exe`（改后缀）上传 → 拒绝，`logs` 记录
13. 上传文件名填 `../../etc/passwd` → 存储不受影响，DB 原始名正常入库，下载时文件名安全
14. 中文文件名下载 → `Content-Disposition` 不乱码
15. MD5 重复：同一成员传同图 → 409；不同成员传同图 → 均成功（D6）
16. 配额满 → 413，`used_space` 未被污染；删除资源后 `used_space` 精确回落
17. 文件夹移动到自身子孙下 → 409
18. 分享链接接口与游客接口响应体中 grep 不到 `status` 标签名与 `original_path`
19. 顶级目录建两个同名文件夹 → 应用层拦截
20. 删除相册 → 级联图片/标签关联/链接快照全部清理，磁盘文件同步删除
